# dstack v0.6.0 preview risk register

Audit freeze: `dc3b95117f518a752c0726ecd44ba7888a25cc49`  
Baseline: `Dstack-TEE/meta-dstack` v0.5.11 and its dstack v0.5.11
submodule  
Related plan: `v0.6.0-release-test-plan.md`  

This is a live register. Add newly discovered risks here rather than burying
them in test results. `Open` means the release needs test evidence or an
explicit waiver; it does not mean a defect has been proven.

| ID | Sev | Status | Risk and evidence | Required mitigation / release evidence |
|---|---|---|---|---|
| R-001 | Critical | Open | Latest VMM/KMS/Gateway will serve v0.5.11 and v0.6.0 images concurrently. Event-log format, guest RPC, cache keys and policy inputs differ, so a false accept, false reject or cross-version cache hit could expose keys. | Pass COMP-03..10 and ATT-01..06; prove cache separation by image, app, TEE variant and event-log format. |
| R-002 | High | Open | PR #646 adds canonical JSON event-log v2 while retaining a v1 compatibility path. Different JSON implementations can disagree on Unicode, number or key ordering. | Cross-language canonical vectors plus tamper vectors (ATT-02..04); archive exact preimages and replay output. |
| R-003 | High | Open | Guest-agent `EmitEvent` was removed (#768). An old application/SDK may call it even if normal v0.5.11 boot does not. | Inventory published SDK behavior; run GST-04 and OLD SDK matrix; document the replacement and breaking behavior. |
| R-004 | Critical | Open | Unified API authentication (#796) covers VMM HTTP/pRPC/UI, while Gateway/KMS admin auth and config names/ports also changed (#674, #802, #804). Wrong rollout order can lock out automation; empty auth may leave admin surfaces exposed. | Stage credentials before enforcement; pass AUTH-01..07; scan listening ports and prove admin RPCs are unreachable without auth. |
| R-005 | High | Open | KMS `ClearImageCache` moved to a dedicated authenticated listener (#802). Old scripts/monitoring may target the former endpoint. | Test old tooling and update runbooks; prove public KMS port cannot execute the RPC and new admin listener is protected. |
| R-006 | High | Open | VMM built-in port forwarding was removed (#795), and networking modes/RPC changed (#756). Existing VM config or operational automation may silently lose ingress. | Detect old field before upgrade, supply migration path, and pass VMM-02/03/07 plus mixed-image networking cases. |
| R-007 | Critical | Open | meta-dstack moved from the v0.5.11 OVMF/Yocto baseline to Yocto 6.0, Linux 6.18, unified TDX/SEV firmware and new image metadata (#64, #68-#70). Firmware/kernel changes can alter measurements and device behavior. | Reproduce measurements on all advertised platforms/sizes; pass OS-01..06 and REG-07; pin final firmware/kernel sources. |
| R-008 | High | Open | `digest.sev.txt` was introduced then removed (meta-dstack #71/#82; dstack #764). External or partially upgraded consumers may still require it. | Search deployment tooling, verify manifest-based replacement, run OS-10 and publish a breaking-change note. |
| R-009 | Critical | Open | NVIDIA image flavors were unified, services became hardware-conditional, and GPU-ready is gated on `nvattest` (meta-dstack #72/#73/#83; dstack #765/#789/#791/#813). A fail-open or startup race could expose an unattested GPU. | Pass OS-07/08 and PLAT-01/02 with absent, slow, invalid, expired and revoked evidence; inspect service ordering. |
| R-010 | High | Open | NVIDIA collateral caching reduces external dependency but risks accepting stale/revoked collateral. | Pin and test TTL/revocation semantics; prove bad OCSP and expired cache fail closed (PLAT-01). |
| R-011 | Critical | Open | Auth contracts migrated to Foundry and KMS ownership became two-step (#252). Live Base storage was rehearsed, but the PR explicitly says other chains were not validated. | Fork-rehearse every deployed chain; compare storage slots; exercise transfer/accept/cancel/error paths before any live upgrade. |
| R-012 | High | Open | New local and per-VM swtpm key providers (#788/#798) create new trust and persistence boundaries. Backup, clone and deletion semantics can cause key loss or cross-VM access. | Threat-model deployment permissions; pass STO-05..07 including clone, reboot, restore and wrong-measurement cases. |
| R-013 | Critical | Open | Verity volumes (#752) add externally supplied data disks and roots. Incorrect device binding or mutable backing data could make unverified content visible. | Pass STO-02 with swapped devices, wrong roots, corruption before/after mount and write attempts; bind roots into measured policy. |
| R-014 | High | Open | LUKS2 keyslot bounds were hardened (#799), indicating attacker-controlled header parsing risk and possible incompatibility with unusual but valid existing volumes. | Run corpus/fuzz and boundary cases; open production-shaped old volumes before and after upgrade; never modify a rejected header. |
| R-015 | High | Open | TDX, GCP, NitroTPM and staged SNP now share more attestation abstractions (#701/#703/#753/#769/#806/#808). Variant confusion or trust-root defaults can accept evidence under the wrong policy. | Negative cross-platform evidence tests; explicit trust roots; assert reported TEE variant and platform-specific binding in PLAT-03..07. |
| R-016 | High | Open | Guest compose version, launch token and GPU requirements now gate boot (#754/#763/#765). Default/omitted-field semantics affect old images and rollback. | Test absent, old, future and malformed fields; ensure failure occurs before secrets/workload; document rollback policy. |
| R-017 | Medium | Open | Gateway DNS resolver caching and WireGuard refresh behavior changed (#740/#741). Stale state or refresh storms can cause outage during rolling upgrade. | Load-test address changes, stale handshakes and Gateway restart; track p95/p99 and recovery time (GKW-02..04). |
| R-018 | High | Open | meta-dstack history was imported into the monorepo by #770. Build paths, release automation, submodules and artifact selection changed; auditing only `dstack v0.5.11..master` misses the independent meta-dstack range. | Preserve the separate 16-PR inventory; run both native/container clean builds and validate artifact manifests/tags. |
| R-019 | Medium | Open | Current master is not immutable. The earlier inventory contained 107 dstack PRs; after #646 it contains 108. Any later merge invalidates counts and coverage mapping. | Freeze preview tag; rerun Appendix A and regenerate `v0.6.0-pr-inventory.json` if HEAD differs. |
| R-020 | Medium | Open | The candidate spans 1,256 dstack commits plus 177 meta-dstack commits, several clouds and hardware types. Preview infrastructure may not cover every advertised path. | Require platform-owner sign-off; label unexecuted cases `Blocked`, not `Pass`; narrow advertised support or explicitly waive with rationale. |

## Risk update rules

* Change `Open` to `Mitigated` only with a test/evidence link.
* Change it to `Accepted` only with owner, rationale and expiry/revisit date.
* A discovered defect gets its own issue; keep the risk row and link the issue.
* Re-audit this file whenever master advances, an artifact is rebuilt, or a
  release waiver changes.
